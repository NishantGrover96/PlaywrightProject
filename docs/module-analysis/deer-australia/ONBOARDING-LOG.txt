ISSUES ENCOUNTERED AND RESOLUTIONS
--------------------------------------------------------------------------------

ISSUE 1 - PowerShell execution policy blocked npm
  Symptom : "npm : File cannot be loaded because running scripts is disabled"
  Cause   : Default PowerShell execution policy was "Restricted"
  Fix     : Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser -Force

ISSUE 2 - new-client.ps1 wizard used wrong Client ID ("deeraus")
  Symptom : Config files created under "deeraus" instead of "deer-australia";
            mismatched with catalog files and dashboard entries built under
            "deer-australia"
  Cause   : User entered "deeraus" as the Client ID during the wizard
  Fix     : Renamed all three wizard-generated files:
              config/clients/deeraus.json      -> deer-australia.json
              config/users/deeraus/            -> deer-australia/
              dashboard/catalogs/deeraus-manifest.json -> deer-australia-manifest.json
            Updated clientId field inside each file.
            Updated config/repos.local.json key from "deeraus" to "deer-australia".

ISSUE 3 - Wrong Production URL entered in wizard
  Symptom : Production URL set to "https://23coop.deere.com" (incorrect)
  Cause   : Previous session typo carried over
  Fix     : Updated production.baseUrl in config/clients/deer-australia.json to
            "http://deereaustraliauat.channel-fusion.com"

ISSUE 4 - Deer Australia not appearing in dashboard client dropdown
  Symptom : Dashboard /api/clients returned only 3 clients; deer-australia missing
  Cause   : PowerShell 5.1 Set-Content -Encoding utf8 writes a UTF-8 BOM
            (bytes EF BB BF) at the start of JSON files.
            Node.js JSON.parse() rejects BOM-prefixed content with:
            "Unexpected token '', '{ "c"... is not valid JSON"
  Fix     : Stripped BOM from all wizard-generated JSON files using:
              $bytes = [System.IO.File]::ReadAllBytes(path)
              $bytes = $bytes[3..($bytes.Length-1)]   # remove EF BB BF
              [System.IO.File]::WriteAllBytes(path, $bytes)
            Patched scripts/new-client.ps1 New-JsonFile and Update-RepoRegistry
            functions to use [System.IO.File]::WriteAllText with
            New-Object System.Text.UTF8Encoding $false (no BOM) for all future runs.
  Note    : Dashboard server restart required because catalog-manifest.json is
            not watched by the file watcher (only dashboard/catalogs/ is watched).

ISSUE 5 - Features not appearing after client showed in dropdown
  Symptom : Selecting "Deer Australia" showed Coop module but no feature
            checkboxes in the dashboard
  Root cause A: catalog-manifest.json entries for deer-australia used field
                "client": "deer-australia" but catalog-service.js reads
                "clientId" field -> fell back to "demoportal", features were
                registered under wrong client
  Fix A   : Renamed "client" to "clientId" in both deer-australia entries in
            dashboard/catalog-manifest.json
  Root cause B: catalog-service.js had no fallback for "client" field
  Fix B   : Patched _loadLegacyManifest in catalog-service.js:
              clientId: entry.clientId || entry.client || 'demoportal'

ISSUE 6 - Smoke test failed with wrong Playwright project names
  Symptom : Error: Project(s) "setup", "chromium" not found.
            Available: "setup-deer-australia", "chromium-deer-australia", ...
  Cause   : client-service.js getProjectsForRole() has hardcoded defaults
            'setup' / 'chromium' for dealer. New (non-legacy) clients get
            per-client project names: setup-{clientId} / chromium-{clientId}
  Fix     : Added roleProjects override to authentication block in
            config/clients/deer-australia.json:
              "roleProjects": {
                "dealer":        ["setup-deer-australia", "chromium-deer-australia"],
                "dealer-custom": ["setup-deer-australia", "chromium-deer-australia"],
                "admin":         ["setup-deer-australia-admin", "chromium-deer-australia-admin"],
                "admin-custom":  ["setup-deer-australia-admin", "chromium-deer-australia-admin"]
              }
            client-service.js already checks cfg.authentication.roleProjects as
            first-priority override, so no server restart was needed.
